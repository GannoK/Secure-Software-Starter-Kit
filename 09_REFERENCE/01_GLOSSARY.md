# Beginner glossary

**API** — A defined way for software components to communicate.

**Authentication** — Proving who you are.

**Authorization** — Deciding what an authenticated identity is allowed to do.

**CI/CD** — Automated systems that test, build, and sometimes deploy software.

**Commit** — A recorded source-control checkpoint.

**DAST** — Security testing performed against a running application.

**Dependency** — Third-party or external software your project uses.

**Least privilege** — Giving a person/service/tool only the permissions it needs.

**RAG (Retrieval-Augmented Generation)** — Giving an AI relevant external/project information at answer time through retrieval.

**Rollback** — Returning to a known earlier state after a bad change.

**SAST** — Static Application Security Testing: analyzing source/code for security-relevant patterns.

**SBOM** — Software Bill of Materials: an inventory of software components.

**SCA** — Software Composition Analysis: analysis of dependencies, often including known vulnerabilities and licenses.

**Secret** — Password, API key, token, private key, or similar credential.

**Supply chain** — The people, tools, packages, services, and build systems involved in creating software.

**Threat model** — A structured way to identify what needs protection, who/what might threaten it, and what controls/tests are needed.

**Trust boundary** — A place where data or control moves between areas with different security assumptions.

**Verification** — Gathering evidence that the observed result matches the intended result.
