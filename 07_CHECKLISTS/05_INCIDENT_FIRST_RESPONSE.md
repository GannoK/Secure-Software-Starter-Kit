# Incident first response checklist

For a suspected security incident:

- [ ] Do not destroy evidence.
- [ ] Record time and observed symptoms.
- [ ] Identify affected system/account/data.
- [ ] Preserve relevant logs and state.
- [ ] Limit further damage using the least disruptive safe containment.
- [ ] Rotate/revoke credentials only when appropriate and record what changed.
- [ ] Avoid random cleanup/reinstallation before evidence is preserved.
- [ ] Identify the last known-good state.
- [ ] Separate confirmed compromise from suspicion.
- [ ] Keep an action timeline.
- [ ] Determine notification/legal/compliance obligations with qualified help where applicable.
- [ ] Fix root cause before declaring recovery.
- [ ] Verify recovery and monitor for recurrence.

For serious incidents, regulated data, safety-critical systems, or legal exposure, involve qualified incident-response/security/legal professionals.
